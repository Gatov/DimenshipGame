# Start Screen + Solution Structure — Design

Date: 2026-07-27
Status: Approved

## Goal

Stand up the repository's project structure — a Godot 4.7.1 .NET game project plus engine-free C# logic libraries and a test project, all in one solution — and ship the game's start screen as the first vertical slice through that structure.

The start screen is deliberately small. Its job is to prove the whole chain works: a Godot scene calls into `Dimenship.Core`, and `Dimenship.Core` is covered by tests that run without the engine.

## Current state

- `DimenshipGame.sln` at the repo root: valid but empty (no projects).
- `dimenship/` holds a Godot 4.7.1-mono project: `project.godot` with `config/name="Dimenship"`, `dotnet/project/assembly_name="Dimenship"`, mobile renderer, d3d12 on Windows, `canvas_items`/`expand` stretch.
- No `.csproj` exists anywhere yet. Godot has never generated its C# project.
- `dimenship/start_game_screen.tscn` is a bare `Node2D` placeholder.
- No main scene is configured, so the project has no entry point.
- Installed .NET SDKs: 6.0.428, 9.0.312, 10.0.203. No 8.0 SDK.

## Repository layout

```
DimenshipGame.sln
Directory.Build.props
docs/superpowers/specs/
dimenship/                          Godot project (stays where it is)
  Dimenship.csproj                  Godot.NET.Sdk 4.7.1
  project.godot
  scenes/StartScreen.tscn
  scenes/Game.tscn                  placeholder target for Play
  scripts/StartScreen.cs
src/Dimenship.Core/
  Dimenship.Core.csproj
  GameInfo.cs
tests/Dimenship.Core.Tests/
  Dimenship.Core.Tests.csproj
  GameInfoTests.cs
```

Reference direction, strictly one-way:

- `Dimenship.csproj` → `Dimenship.Core.csproj`
- `Dimenship.Core.Tests.csproj` → `Dimenship.Core.csproj`
- `Dimenship.Core.csproj` → nothing

`Dimenship.Core` never references `GodotSharp`. That is the invariant that keeps `dotnet test` runnable without the engine, and it is what makes future logic libraries cheap to add: each new one is another `src/<Name>/` with the same rules.

## Projects

### dimenship/Dimenship.csproj

```xml
<Project Sdk="Godot.NET.Sdk/4.7.1">
  <PropertyGroup>
    <TargetFramework>net8.0</TargetFramework>
    <EnableDynamicLoading>true</EnableDynamicLoading>
    <RootNamespace>Dimenship</RootNamespace>
  </PropertyGroup>
  <ItemGroup>
    <ProjectReference Include="..\src\Dimenship.Core\Dimenship.Core.csproj" />
  </ItemGroup>
</Project>
```

The file name must stay `Dimenship.csproj` and must sit next to `project.godot`, because Godot resolves the C# project from `dotnet/project/assembly_name`.

Hand-written rather than generated by the editor's *Project → Tools → C# → Create solution*, which would emit a second `dimenship/Dimenship.sln` competing with the root solution.

### src/Dimenship.Core/Dimenship.Core.csproj

Plain `Microsoft.NET.Sdk` class library, same TFM as the Godot project.

```csharp
namespace Dimenship.Core;

public static class GameInfo
{
    public const string Title = "Dimenship";
    public const string Version = "0.1.0";

    public static string DisplayVersion => $"v{Version}";
}
```

### tests/Dimenship.Core.Tests/Dimenship.Core.Tests.csproj

`Microsoft.NET.Sdk` with `IsPackable=false`, packages: `NUnit` 4.x, `NUnit3TestAdapter`, `Microsoft.NET.Test.Sdk`.

`GameInfoTests` covers `DisplayVersion` — that it is prefixed with `v` and carries the `Version` value. Constants themselves are not asserted against their own literals; that tests nothing.

### Directory.Build.props (root)

```xml
<Project>
  <PropertyGroup>
    <Nullable>enable</Nullable>
    <LangVersion>latest</LangVersion>
  </PropertyGroup>
</Project>
```

Applies to all three projects, including the Godot one. It does not override anything `Godot.NET.Sdk` needs.

## Target framework

`Godot.NET.Sdk/4.7.1` expects `net8.0`. All three projects use the same TFM so the project references resolve without a downgrade warning.

No .NET 8 SDK is installed, but SDK 10 builds `net8.0` by restoring `Microsoft.NETCore.App.Ref` from NuGet. This is verified by building, not assumed. If the restore fails, the fallback is to raise all three projects to whatever TFM `Godot.NET.Sdk/4.7.1` accepts — the TFM must stay identical across the three either way.

## Start screen

`dimenship/scenes/StartScreen.tscn`:

```
Control  "StartScreen"          full-rect anchors, script scripts/StartScreen.cs
├── ColorRect  "Background"     full-rect, dark fill
└── CenterContainer             full-rect
    └── VBoxContainer           theme separation 24, alignment center
        ├── Label  "TitleLabel"     text set at runtime, large font
        ├── Label  "VersionLabel"   text set at runtime, small, dimmed
        ├── Button "PlayButton"     custom_minimum_size 280x64
        ├── Button "SettingsButton" custom_minimum_size 280x64, disabled
        └── Button "QuitButton"     custom_minimum_size 280x64
```

`scripts/StartScreen.cs` on `_Ready`:

- `TitleLabel.Text = GameInfo.Title`
- `VersionLabel.Text = GameInfo.DisplayVersion`
- wires `Pressed` handlers in code (`PlayButton.Pressed += OnPlayPressed`), not through editor signal connections, so the wiring lives beside the handlers and survives renames
- `PlayButton.GrabFocus()` for keyboard navigation
- hides `QuitButton` when `OS.GetName()` is `Android`, `iOS`, or `Web`, where quitting is not a thing the platform wants

Handlers:

- Play → `GetTree().ChangeSceneToFile("res://scenes/Game.tscn")`
- Settings → none; the button ships `Disabled = true` until a settings screen exists. A visibly inactive button is honest; a button that silently does nothing is not.
- Quit → `GetTree().Quit()`

Node lookups use exported `NodePath`-free `GetNode<T>` calls against the fixed paths above.

`dimenship/scenes/Game.tscn` is a `Node2D` with a centered label reading that it is a placeholder, so pressing Play produces visible evidence the scene switch works.

## project.godot changes

- `run/main_scene="res://scenes/StartScreen.tscn"`
- `display/window/size/viewport_width=1920`, `viewport_height=1080` (desktop landscape base)

Existing stretch settings (`canvas_items` / `expand`) are kept; combined with anchors and containers the menu scales to other window sizes.

`dimenship/start_game_screen.tscn` is deleted, replaced by `scenes/StartScreen.tscn`.

## .gitignore

Root `.gitignore` gains `.idea/`, `.vs/`, `*.user`. `bin/`, `obj/` are already there; `dimenship/.gitignore` already covers `.godot/`.

## Build order

Tests come before the code they cover:

1. `Dimenship.Core.csproj` + `Dimenship.Core.Tests.csproj`, `GameInfoTests` first, then `GameInfo` until green.
2. `Dimenship.csproj`, added to the solution, referencing Core.
3. Scenes, script, `project.godot` edits.

## Verification

- `dotnet build DimenshipGame.sln` — clean, all three projects.
- `dotnet test` — `GameInfoTests` green.
- Godot editor opens the project, imports the scenes, and running it shows the start screen with a working Play button.

The third item cannot be checked from this environment: the Godot editor is an unextracted zip in `~/Downloads` and is not on `PATH`. That step is the user's, or waits until an editor path is provided. It will not be reported as verified before then.

## Out of scope

Settings screen, audio, save/load, real gameplay, art beyond the default icon, export presets, CI.
