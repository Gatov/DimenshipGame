# Settings Menu — Implementation Plan

Status: Built

**Goal:** A working settings menu with Gameplay, Graphics and Sound tabs, reachable from the start
screen and from the shell's Vessel menu, persisted to `user://settings.json` and applied to the
engine as it is changed.

**Spec:** `docs/superpowers/specs/2026-08-20-settings-design.md`.

**Architecture:** The same split the window layout already uses. The state and its serializer are
engine-free and unit-tested in `Dimenship.Shell`; the file I/O, the engine writes and the UI are in
`dimenship/scripts/ui/`. `Dimenship.Core` is untouched and no setting reaches a save.

## Why

`dimenship/scenes/StartScreen.tscn` has shipped a disabled Settings button since the start screen
landed, on the recorded principle that a visibly inactive button is honest and a button that
silently does nothing is not. This is the work that button was a placeholder for.

It also brings two things into the project for the first time: an audio bus layout, because a
volume setting has to have somewhere to land, and a modal surface, because there was no dialog
anywhere in the codebase to copy.

## Tasks

- [x] **1. `SettingsState`, `ScreenSizes`, `SettingsSerializer` in `Dimenship.Shell`.**
      Records for the graphics and sound groups, ratios in permille, window mode as a named enum.
      `ScreenSizes.Offered` filters the 16:9 ladder against the screen as pure arithmetic, so the
      rule that a player is never offered a window larger than their display is testable without a
      display. The serializer mirrors `LayoutSerializer` — degraded input yields a valid state plus
      warnings, never an exception — with every DTO field nullable, because a missing volume would
      otherwise deserialize to silence.

- [x] **2. Tests in `Dimenship.Shell.Tests`.** `SettingsSerializerTests` covers round trip, null,
      malformed JSON, unknown and ordinal-spelled enum names, clamped volumes, clamped scale,
      clamped resolution, a missing group, a missing field, and an unknown field from a newer
      build. `ScreenSizesTests` covers both-axis filtering, an off-ladder current size, a current
      size larger than the screen, and ordering.

- [x] **3. Godot plumbing.** `SettingsStore` (`user://settings.json`, `.bad` quarantine, warnings
      to `GD.PushWarning`) mirrors `LayoutStore` line for line. `Settings` is the static holder and
      the only way in — apply, preview, persist, announce. `SettingsApplier` is the only place a
      setting reaches `DisplayServer`, `AudioServer` or the root viewport. `AudioBuses` names the
      three buses and creates any that are missing.

- [x] **4. `default_bus_layout.tres` and the `[audio]` section in `project.godot`.** Master, Music
      and SFX. The project setting is stated rather than left implicit, because a layout that
      silently failed to load would leave the sliders writing to buses that do not exist.

- [x] **5. `SettingsOverlay` and the theme entries it needs.** A `Control` over the running scene
      with its own theme, a tab strip copied from the programming view, and rows in the label /
      reason / control shape the panels already use. `ShellTheme` gains `HSlider` — the one new
      control — including a handle texture generated from a palette colour.

- [x] **6. Wiring.** The start screen's button loses `disabled` and gains a handler; the Vessel
      menu gains `Settings…`, routed through a new `ShellActions.SettingsRequested`;
      `ShellActions.Suspended` holds the accelerators while the menu is up; `ShellRoot` toggles the
      backdrop image and `FrostPane` toggles itself.

- [x] **7. Documentation.** This plan, the spec beside it, and `CLAUDE.md`.

## Verification

`dotnet test tests/Dimenship.Shell.Tests` is where the tested half lives. The Godot half needs the
editor, which is not on `PATH` in the session this was written in, so **no visual behaviour below
was verified here.** It is the project owner's step:

1. Start screen → **Settings** opens the menu; Escape and **Back** close it.
2. Graphics → Borderless fullscreen and back to Windowed; the resolution dropdown greys out in
   fullscreen with its reason shown, and re-applies on return.
3. Interface scale to 130%; quit and relaunch, and it is still 130%.
4. Nebula backdrop off → panels fall back to flat fills, the frost row greys out with its reason,
   and turning the backdrop back on restores the frost choice rather than resetting it.
5. Sound → each slider moves `AudioServer.GetBusVolumeDb` on its bus, and each toggle moves
   `GetBusMute`.
6. Play → **Vessel → Settings…** opens the same menu; `Space` does not pause while it is up, and
   pauses again once it closes.
7. Corrupt `user://settings.json` by hand and relaunch: the game opens on defaults, the file is
   quarantined to `settings.json.bad`, and the warnings name what was wrong.
8. Open the project in the Godot editor once, so the new scripts get their `.cs.uid` sidecars and
   `default_bus_layout.tres` gets its resource uid, and commit those.
